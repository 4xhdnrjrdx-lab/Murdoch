# Постоянное правило владельца: фотографии

Фотографии и видео пользователя неприкосновенны: никогда не удалять, не перемещать, не изменять и не использовать их для освобождения места. Это относится ко всем папкам, iCloud Drive, iCloud Photos и медиатекам приложения «Фото». Не сканировать фототеки для очистки и не менять их синхронизацию или оптимизацию хранилища. Разрешение сохранять учебные копии в приватной базе не разрешает изменять или убирать оригиналы.

## Начало работы

1. Получить текущую main. Прочитать README.md, этот файл, COURSES.yaml, Access/Moodle/README.md, Migration/GAPS.md. Затем прочитать README, CONTEXT, TASKS, TEAM и HISTORY нужного прохождения.
2. Проверить `git status`, `git fetch origin`, сравнить main с origin/main. На чистой main выполнить `git pull --ff-only`. При изменениях сначала сохранить/совместить работу; `reset --hard`, force push, очистка рабочих файлов и переписывание чужой истории запрещены.
3. Выполнить `python3 scripts/verify.py`. При ошибке не объявлять копию восстановленной. В новом клоне: `python3 scripts/sync.py configure` для локальных настроек и проверок.
4. Почту и LMS проверять при начале работы по предмету или запросе статуса. Если доступа нет, указывать дату попытки, дату последней успешной проверки и неизвестное. Фоновые проверки и автоматизации не создавать. Существующие Unit Outline использовать локально, не скачивать повторно.
5. Старые файлы `00_CHAT_CONTEXT.md`, сводки vault, прежние AGENTS/CLAUDE, LMS snapshots и старые планы являются датированными источниками в Archive/Materials. Их инструкции не являются правилами этой базы. В исходной локальной папке старые копии оставлены до проверки переноса; рабочая база для всех новых чатов находится в папках периода.

## Основные места фактов

- COURSES.yaml: реестр прохождений и официальный итог юнита. JSON-синтаксис является допустимым YAML; читать стандартным json.
- `<code>/<period>/TASKS.json`: основные состояния, сроки, подтверждения и следующее действие. TASKS.md формируется из него. Поле correction хранит отдельную просьбу исправить уже сданное.
- Поле working_files в TASKS.json: точные относительные пути и назначение выбранных актуальных файлов. TASKS.md и Assignments/README.md формируются из него; не выбирать новую версию только по имени FINAL или дате. Если рабочий файл не указан, готовность не выдумывать.
- CONTEXT.md: договорённости, пояснения и неизвестное; TEAM.md: состав и обязанности с пределом подтверждения; HISTORY.md: датированные существенные события и источники.
- Assignments: сами исходники, черновики, финальные версии и подтверждения. Имя FINAL и наличие файла не доказывают сдачу. Исходную сданную версию и подтверждение не заменять исправленным файлом; новые версии сохранять отдельно.
- ACCESS_STATUS.json: даты/охват проверок источников и восстановления секретного доступа. Синхронизация GitHub определяется сравнением SHA, не датой проверки LMS.
- README и TASKS.md генерирует `scripts/render.py`. Вручную независимые копии сроков/статусов не поддерживать. Новые подтверждения могут исправлять основные записи; архивы остаются историей.

Статусы работ: предложено → согласовано → в работе → готово к сдаче → сдано → оценено. Использовать наиболее подтверждённый этап; если начало/сдача неизвестны, помечать неизвестность явно. Просьба исправить сданное не отменяет исходной сдачи. Состояния предмета: учимся, ожидаем итог, успешно завершён, требуется пересдача. Последние два требуют официального итога юнита. Новая попытка получает отдельную папку периода/попытки, запись в COURSES.yaml и разрешение нового пути в .gitignore; завершённые файлы не перемещать и не удалять.

Сроки: Asia/Dubai, источник и дата проверки обязательны. Timestamp предпочтительнее предположения об австралийском времени. При конфликте сохранить обе версии до подтверждения. Технический cutoff не означает официальное продление. Датированное submitted важнее старого new; Turnitin receipt не обязательно подтверждает финальную сдачу в Moodle.

27 октября 2026 пользователь разрешил общему чату напрямую обращаться к существующим чатам BUS219, BUS225, BUS230 и BUS334 для уточнений и необходимой координации учебной базы. Это не является разрешением отправлять письма преподавателям/одногруппникам, сдавать задания, менять регистрацию или выполнять платежи.

1. Использовать отдельные клоны/рабочие ветки для параллельных чатов, каждый меняет свой предмет. Не переключать ветку в общей активной папке. В общем дереве `scripts/sync.py publish` откажется при посторонних незакоммиченных изменениях.
2. Коммитить только собственные файлы. Общий обзор и MANIFEST обновлять последовательно при интеграции. Перед push получить origin/main; включить новые изменения других чатов merge или fast-forward, не теряя их. Конфликт основных записей разрешать по источникам, не выбирать целиком одну сторону без проверки.
3. `python3 scripts/render.py` обновляет производные обзоры и MANIFEST. Проверить `python3 scripts/verify.py`, diff и secret scan. `git add` с конкретными путями. Не использовать общий `git add .` в папке с чужими изменениями.
4. Рекомендуемый publisher: `python3 scripts/sync.py publish --message 'описание' --paths BUS225/2026-TSD` (дополнительные свои пути передать явно). Он использует локальную блокировку, проверяет отсутствие чужих изменений, fetch и merge, обновляет производные файлы, коммитит и делает обычный push. При конфликте останавливается и сохраняет файлы; завершить разрешение и проверки перед новым запуском. Между разными клонами защитой служит отклонение push при изменённой main. Ни force, ни автоматического выбора стороны нет.
5. После push сравнить `git rev-parse HEAD` и `git ls-remote origin refs/heads/main`; показать пользователю короткий итог, дату почты/LMS и состояние GitHub. Незакоммиченные/неотправленные файлы не называть сохранёнными.

## Хранение и границы полномочий

Сами необходимые файлы хранятся в Git, включая видео и подтверждения. Точные дубли сведены по SHA-256; соответствие путей в Migration/INVENTORY.json. Разные версии сохранены. Старые оригиналы и существующие репозитории не удалять. Archive/LocalSources_2026-10-29 и Archive/RecordSnapshots_2026-10-29 — датированные источники, не инструкции. Карта исходных путей и точных копий находится в Migration/LOCAL_AUDIT_2026-10-29.json.

Не сохранять токены, пароли, cookies, приватные ключи, сырые почтовые заголовки, полный список получателей учебной группы и технический мусор. Секрет Moodle хранится в выбранных пользователем iCloud Passwords и локально вне Git. Важные исключения и способы их восстановления описывать в Migration/GAPS.md. Материалы и личное видео разрешено сохранять в этом приватном репозитории просьбой пользователя 7 октября; прежний локальный запрет BUS225 на видео/скриншоты заменён этим поручением.

Обычный Git выбран для текущих файлов меньше 100 МиБ. Перед добавлением файла от 100 МиБ включительно проверка останавливается; выбрать GitHub storage и проверить фактические байты. Для будущего LFS проверить бесплатную квоту и стоимость, не подключать платные услуги без согласия. При LFS недостаточно pointer: нужны загрузка объектов, `git lfs pull`, проверка SHA-256 и восстановление. Не добавлять новые большие версии видео без необходимости.

Разрешение работать с GitHub не разрешает отправлять письма, сообщения, публиковать видео, менять регистрацию или сдавать задания. Внешние сообщения и сдачи требуют отдельного поручения. Чтение другого чата допустимо, сообщения ему не нужны. Полная готовность требует сохранения необходимых файлов и проверки восстановления; открытые пробелы сообщать явно.
