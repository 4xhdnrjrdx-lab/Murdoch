# Полное восстановление Murdoch

Нужен доступ к приватному [репозиторию Murdoch](https://github.com/4xhdnrjrdx-lab/Murdoch), независимый от старого Mac. На iPhone можно читать README, статусы и скачивать отдельные файлы через Safari/GitHub. Для полного восстановления понадобится любое устройство с Git и Python 3.10+ либо доступная среда, куда разрешено клонировать приватную базу.

## Получить все файлы

1. Войти в GitHub и пройти собственную 2FA. Восстановление аккаунта и коды хранить вне старого Mac. Токены не вставлять в URL clone или чат.
2. В новой пустой папке:

```sh
git clone https://github.com/4xhdnrjrdx-lab/Murdoch.git Murdoch
cd Murdoch
python3 scripts/sync.py configure
python3 scripts/verify.py
git fsck --full
python3 scripts/sync.py status
```

При CLI GitHub можно использовать `gh auth login` и `gh repo clone 4xhdnrjrdx-lab/Murdoch`, не печатая пароль/token. Все нынешние файлы хранятся обычным Git; отдельный LFS-install или pull не нужен. Видео BUS225 клонируется вместе с остальными байтами. Точные дубли хранятся один раз; Migration/INVENTORY.json связывает прежние имена с сохранённым файлом.

`verify.py` сверяет состав сохраняемой базы, размер и SHA-256 каждого файла, основные ссылки, состояния, источники и распространённые утечки секретов, включая XML внутри Word/PowerPoint/Excel. Это проверка известных типов секретов, не обещание распознать любые возможные персональные данные. Исторические ссылки старых материалов проверяются через инвентаризацию; они не являются актуальной навигацией.

На iPhone GitHub не даёт терминал для полной SHA-сверки. Скачать отдельный документ можно через его страницу; для большого видео Download raw file. Если скачиваете ZIP через Code → Download ZIP, он содержит текущие обычные Git-файлы, но не историю коммитов; полный clone сохраняет историю. Для ZIP можно запустить verify.py на распакованной папке, однако sync.py требует clone.

## Восстановить Moodle

Следовать [Access/Moodle/README.md](Access/Moodle/README.md). Ключ находится в выбранных пользователем Apple Passwords/iCloud, либо выпускается заново после SSO/MFA. В Git его нет. Вводить его только скрытым запросом configure, не в сообщение. Дата актуальной проверки должна обновиться только после успеха API, отдельно от GitHub-синхронизации.

## Продолжить в новом чате

Скопируйте запрос:

> Продолжаем мою учёбу в приватном репозитории 4xhdnrjrdx-lab/Murdoch. Получи текущую main, прочитай README.md, AGENTS.md, COURSES.yaml и Migration/GAPS.md, затем CONTEXT.md, TASKS.md, TEAM.md, HISTORY.md нужного предмета. Проверь почту и LMS при начале работы, укажи дату и предел доступа. Продолжай на основании последних подтверждений; сохрани существенные изменения обратно в GitHub и проверь SHA. Не отправляй сообщения и не сдавай задания без отдельного поручения.

Новый чат должен иметь авторизованный доступ к приватному GitHub и, для обновления сведений, отдельный доступ к почте/LMS. Предыдущие чаты и исходная папка Mac для чтения сохранённой базы не нужны. Если основной токен недействителен, читать сохранённые данные можно, новые LMS-статусы остаются неизвестными.

Проверка окончательной копии и параллельных изменений: [отчёт](Verification/RESTORE_REPORT.md). Незавершённые источники и доступ: [GAPS.md](Migration/GAPS.md). Эта проверка не является разрешением на удаление исходников. Фотографии и видео неприкосновенны по AGENTS.md, даже при наличии резервной копии. Любую будущую работу с остальными локальными файлами рассматривать отдельно.

## Аудит перед упорядочением Mac: 29 октября 2026

[Отчёт и точка продолжения](Verification/MAC_AUDIT_2026-10-29.md), [полная карта файлов](Migration/LOCAL_AUDIT_2026-10-29.json). Дополнительные источники находятся в Archive/LocalSources_2026-10-29. Они не создают новые прохождения курсов и не меняют текущие решения.

После клонирования сначала читать корневые правила и TASKS.json: working_files указывает актуальный комплект. Старый CONTEXT сохранён как снимок, текущий CONTEXT содержит только действующие договорённости и неизвестное. Для существующей локальной папки с изменёнными файлами нельзя использовать reset/clean: полный свежий clone в другое место безопаснее, исходники остаются на месте.

Если LOCAL_AUDIT указывает action existing_history, точные байты находятся в Git-истории. В полном клоне получить их командой `git cat-file blob <git_blob>` с перенаправлением в новый файл вне базы. Не подставлять туда source-путь и не перезаписывать оригинал. ZIP текущей ветки не содержит исторические blobs; для такого восстановления нужен полный clone.
