Код: [moodle.py](moodle.py). Настройки без секретов: [config.example.json](config.example.json). Модуль не обращается в сеть при импорте и разрешает только явно перечисленные операции чтения. POST служит транспортом API; методов отправки работ и сообщений нет.

7 октября 2026 после первого `invalidtoken` пользователь обновил ключ через SSO/Microsoft Authenticator. Новый ключ проверен этим чатом: userid 257560, доступны BUS219, BUS225, BUS230 и BUS334. Точный срок нового ключа неизвестен. Истечение 4 октября относится к старому ключу. Текущий результат хранится в [ACCESS_STATUS.json](../../ACCESS_STATUS.json); обновлённая исходная заметка сохранена отдельно от старой версии в [архиве](../../Archive/LegacyNotes/murdoch_moodle_api_2026-10-07.md).

На нынешнем Mac ключ находится только в `/Users/king1/murdoch-moodle/.moodle_token`, с правами 0600. Исходный клиент работает и остался на месте. В локальном игнорируемом `Access/Moodle/config.json` указан путь к существующему ключу; самого значения нет. Поэтому текущая команда `python3 Access/Moodle/moodle.py check` уже работает. На другом устройстве этот конфиг не восстанавливается; ключ настраивается отдельно, без необходимости иметь старый Mac.

## Хранение с доступом через iPhone

Пользователь выбрал «Пароли» Apple с синхронизацией iCloud. 7 октября подтвердил сохранение нового ключа, проверку записи на iPhone, выполненный configure и результат check access: ok. Независимое хранение секрета подтверждено пользователем; API дополнительно проверен этим чатом. Точный срок действия неизвестен.

Порядок сохранения и восстановления (в этой сессии выполнен пользователем):

1. В «Пароли» создать запись **Murdoch Moodle API**, сайт `moodleprod.murdoch.edu.au`, имя `35553299`, в поле пароля вставить именно web-service API token. Заметка: «Moodle mobile web service, обновлён 7 октября 2026, срок неизвестен».
2. На Mac можно скопировать текущий ключ в буфер без вывода в терминал:

```sh
pbcopy < /Users/king1/murdoch-moodle/.moodle_token
```

Сразу вставить в запись «Пароли», сохранить, очистить буфер командой `pbcopy < /dev/null`. Не вставлять ключ в чат, issue, ссылку или пример конфигурации. Синхронизировать запись через iCloud «Пароли и связка ключей» и открыть её на iPhone. Пользователь подтвердил, что запись видна на iPhone; пункт закрыт.

3. На новом компьютере получить значение из «Паролей» или выпустить новый ключ через SSO/MFA. В корне клона:

```sh
python3 Access/Moodle/moodle.py configure
python3 Access/Moodle/moodle.py check
```

Ввод скрыт. До замены ключа выполняется проверка API. Новый локальный секрет сохраняется по умолчанию в `.secrets/moodle.token` с правами 0600, вне Git. Пользовательский `--token-file` имеет приоритет над `MOODLE_TOKEN_FILE`, затем локальным `config.json`, затем путём по умолчанию. Относительный token_file из конфига считается от корня клона. Значение token никогда не передавать аргументом команды.

На iPhone записи достаточно для независимого хранения; для API-клиента требуется среда Python на новом компьютере или другая разрешённая пользователем среда. Apple Account, доступ к iCloud, GitHub 2FA и университетский MFA должны восстанавливаться независимо от потерянного Mac; их секреты в Git не хранятся.

## Обновить истёкший ключ без старого Mac

Исходная инструкция `murdoch-moodle/CLAUDE.md` и обновление доступа 7 октября подтверждают сервис **Moodle mobile web service** и SSO. Preferences → Security keys на этом сайте показывал календарный ключ, который оказался непригоден для web-service API. Не использовать его вместо Moodle mobile token.

1. На любом новом компьютере войти в [Moodle](https://moodleprod.murdoch.edu.au/my/) через собственный университетский SSO; пользователь проходит MFA.
2. В Chrome/Edge открыть DevTools → Network, включить Preserve log. Открыть `https://moodleprod.murdoch.edu.au/admin/tool/mobile/launch.php?service=moodle_mobile_app&passport=112233&urlscheme=moodlemobile`.
3. У запроса launch.php найти Response Header Location, начинающийся `moodlemobile://token=`. Весь callback содержит секреты: не делать скриншот, не выводить его в чат и не сохранять HAR. Скопировать его только для следующего скрытого ввода:

```sh
python3 Access/Moodle/moodle.py configure-mobile
```

Клиент декодирует callback локально, выбирает среднее поле `:::`, проверяет API и сохраняет ключ, не печатая его. Если формат изменился, команда останавливается с безопасной ошибкой; обратиться к университетской поддержке или проверить актуальную инструкцию, не угадывать поле. После получения записать новый ключ в выбранный менеджер паролей и очистить Network/буфер. Календарный ключ и пароль аккаунта не заменяют web-service token.

Эта инструкция сохраняет ранее рабочий способ SSO; новый вход повторно в этом чате не выполнялся, так как текущий ключ уже работает.

## Читать данные и материалы

```python
from Access.Moodle.moodle import Client
client = Client()
info = client.call('core_webservice_get_site_info')
contents = client.call('core_course_get_contents', {'courseid': 31305})
```

Course IDs берутся из COURSES.yaml. Сроки timestamp переводить в Asia/Dubai. При начале работы по предмету или запросе статуса прочитать актуальную почту/LMS, сохранить дату, источник и только необходимые сведения. Сырые ответы могут содержать чужие данные; не экспортировать всё автоматически. Фонового мониторинга нет.

Unit Outline уже сохранены в Materials/UnitOutline. Повторно скачивать их запрещено; клиент дополнительно блокирует явные URL outline. Видеолекции BUS230 можно получить командой ниже: список берётся из текущего `core_course_get_contents`, только файлы с MIME video. Unit Outline не скачивается.

```sh
python3 Access/Moodle/moodle.py download-bus230-videos
```

После скачивания проверить состав/хэши, обновить manifest и отправить в GitHub по AGENTS.md. Получение файла и загрузка на GitHub являются разными этапами; успешное API не доказывает облачное сохранение.

## Независимость от этого Mac: уточнение 29 октября 2026

Для восстановления не нужна исходная папка `/Users/king1/murdoch-moodle`. Достаточно полного клона GitHub и ключа из записи **Murdoch Moodle API** в Apple Passwords/iCloud. Пользователь подтвердил сохранение и доступ с iPhone 7 октября; сохранённый ключ продолжает работать 29 октября. Само содержимое записи Apple Passwords ассистент не читает и заново не проверял.

На другом компьютере:

1. Клонировать приватную main и выполнить `python3 scripts/sync.py configure` и `python3 scripts/verify.py`.
2. Выполнить `python3 Access/Moodle/moodle.py configure` и вставить ключ из Apple Passwords в скрытый запрос. Команда создаст локальную игнорируемую `.secrets/moodle.token` и проверит его до сохранения; значение не печатается.
3. Выполнить `python3 Access/Moodle/moodle.py check`; ожидаемый userid — 257560. Путь старого Mac в новом конфиге не нужен.
4. Если ключ истёк или запись потеряна, пройти собственный SSO/MFA и выпустить новый mobile token по инструкции выше. Это также не требует старого Mac.

29 октября клиент из независимого GitHub-клона успешно выполнил site-info с отдельно хранимым ключом, userid 257560. Код исходной старой папки для этой проверки не использовался. Пять старых несекретных файлов доступа дополнительно сохранены в Archive/LocalSources_2026-10-29_Supplement/Legacy_Moodle_Tools только как история; их планировщики и прежние инструкции не запускать.

Ключ не записывается в открытом виде ни в файлы Git, ни в commit, issue или чат. Приватность репозитория не делает опубликованный в его истории ключ удобным хранилищем секретов. Действующая схема: GitHub хранит учебные файлы и код, Apple Passwords — секрет; оба восстанавливаются независимо от Mac. Сохранение в GitHub зашифрованного контейнера потребовало бы отдельного выбранного способа шифрования и независимого хранения пароля; в этой задаче контейнер не создавался.
