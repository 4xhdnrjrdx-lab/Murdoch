Карен отслеживает оценки и прогресс к **проходному ≥50%** по каждому предмету TMD 2026. Дополняет [[karen_study_base]] (там — структура предметов и дедлайны).

## Данные в вольте (`vault-karen`)
- В hub-ноте каждого предмета — раздел **`## Оценки и прогресс`** (сразу под «Дедлайны и задания»). Таблица-**зеркало журнала Moodle**: `| Компонент | Вес | Оценка | Из | Вклад | Статус |`. Вклад = (Оценка/Из)×Вес; строка «оценена», если Оценка и Из — числа. Веса суммируются в 100%.
- **Сводная нота** `subjects/TMD-2026/Оценки — TMD 2026.md` (type: dashboard) — снимок по всем 4 предметам, связана из [[TMD 2026]] (📊). Открыть: `Cmd+O` → «Оценки».
- BUS363 — внутри раздела ещё **чек-лист участия Sessions 1-12** (Assessment 4, 15%): «All students:…» = оцениваемое Participation, сдаётся по сессиям в LMS, пересдачи нет. Сдана 1/12.

## Принцип (важно)
**«Гарантировано» = сумма ФИНАЛЬНЫХ оценок** (консервативно, для вопроса «прошёл ли 50%»). Проекции Moodle (его «Unit total» может показывать больше, экстраполируя средний % сданных на полный вес группы) отмечаются ОТДЕЛЬНО и не считаются собранным. Каждый квиз BUS293 = 3% курса (5×3.00=15%), поэтому Q1-3 = 8.4% locked, а Moodle-проекция ~13.5%.

## Дедлайны — детерминированный ридер (PR #192-193)
- **`jarvis/deadlines.py`** + **`bot._try_fast_deadlines`** (аналог grades): вопрос «какие дедлайны / что висит / что сдавать / что горит» → парс таблиц `## Дедлайны и задания` активных хабов НАПРЯМУЮ (статус-фильтр ⏳/🔄 = не сдано; ВСЕ будущие даты строки; название из frontmatter `title`). Минуя мозг → без «по памяти» галлюцинаций (Карен врала имя MSP200 + пропускала дедлайны). Формат блоками + «🔥 Ближайшее ≤2 недели». Запись/правку/«помоги» (`_DEADLINE_ACTION`) НЕ ловит → мозгу.

## Формат вывода + роутинг (PR #188-191)
- **Вывод блоками** (под Telegram, без markdown — он стрипится): `format_all`/`format_report` дают эмодзи-маркер предмета 📘📗📙📕, под ним `✅ задание: балл → вклад`, `🎯 до 50%: добрать +N% курса — это в среднем ≥X% на остатке R%`, `⏳ ждут: …`. _goal_line показывает И +% курса (50−собрано), И средний балл на остатке (т.к. остаток весит не 100%) — Сэр путался «почему не 33%».
- **⚠️ Вопрос про оценки бот отдаёт САМ, минуя мозг** (`bot._try_fast_grades`, детерминированно, как `_try_fast_reminders`): «оценки по…», «сколько собрал», «сколько по BUS293», «прошёл ли», «оценки по всем» → `format_report/format_all` напрямую в Telegram. Гарантированный формат, без пересказа прозой и без «проверяю» (мозг был ненадёжен: пересказывал/филлерил). **Запись** («поставь 85 за…», «N из M») НЕ ловится fast-grades → идёт мозгу (`update_grade`). Расписание («что по X на неделе») не ловится (нет grade-сигнала). Триггеры: `_GRADES_QUERY`/`_GRADES_UPDATE`/`_GRADES_CODE` в bot.py.

## Hardening 19 июня (адверс-ревью, 4 агента Opus → PR #186)
- **Валидация шкалы**: `update_grade` отвергает score>out_of (напр. «18» в шкале /3) и отрицательное → подсказка «X из Y» (закрыт риск ложных данных).
- **Маркер `<!-- grade-auto -->`**: `_refresh_totals` трогает строку `**Прогресс:**` ТОЛЬКО по маркеру; рукописные без маркера не затираются. Все 4 хаба мигрированы под маркер, нюансы (BUS279 «промежут.», BUS363 участие, BUS293 Moodle-проекция) — в отдельных `_курсивных_` строках.
- **`refresh_dashboard()`**: сводная нота авто-регенерится из `compute()` при каждом `update_grade` (между маркерами `grades-auto`) — не расходится с хабами.
- **Вердикт**: required_avg>100 / нет остатка → «≥50% недостижимо, пересмотр/апелляция».
- **Точный type** (`^type: subject$`): `subject-hub` (Учёба.md) больше не ложно-предмет.
- **Атомарная запись** (`config.atomic_write`).
- **Реверификация (PR #187)**: повторный адверс-проход (Opus, 3 линзы) подтвердил все 6 фиксов закрытыми + нашёл 2 латентных бага ОТ самих фиксов → закрыты: (a) `refresh_dashboard` требует ОБА маркера grades-auto (иначе молчаливый no-op при битом end); (b) граница секции рвётся по любому заголовку `#{2,}\s` (в `_grade_section` и insert-ветке `_refresh_totals`) — H3-чек-лист BUS363 не попадает в парс. _Урок: после фиксов гонять адверс-проход ЗАНОВО (подтвердить закрытие + регрессии)._
- **Отложено** (не P1): вес обязан быть в %; <6 колонок молча теряет строку; голос idёт fast без MCP (оценки голосом не сработают — Карен в основном чат); связка участия A4 с чек-листом сессий; накопление округления (≤0.05%).
